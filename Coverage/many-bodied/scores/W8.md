## 0 · Purpose

## 1 · Slice 29 · The Unwritten filled — the app side

### 1.1 The Waiting Room reads every role

- **Site:** `AirtableService.fetchWaitingRoles()` (W2 §1.5).
- **Becomes:**
  - filter `AND({Type}='Waiting Role', OR({Status}='Live',{Status}='Staged'))`, sort `Sort Order` asc, **every page** (the shared `fetch` paging — C6 may write several hundred rows);
  - fields requested by ID: `Name`, `Linked Story`, `Sort Order`, `Status` — **not** `Excerpt`, `Codex ID`, `Teller`, `Room` (backstage for the pipeline; never on device).
- **Scene (W2 §5.2, unchanged in kind, made for hundreds):** the column under the Unwritten's stories in GameView stays a plain column (Lora italic 14, `inkTertiary`, line spacing 18), but it is a `LazyVStack` so hundreds lay out lazily. **No heading, no count, no "waiting" word, no "+N", no "more".** The column simply goes on as far as the roles go. The gaps (roles whose `Linked Story` is set) keep their W2 form: an empty space the width of the name, a dotted underline; tap → the story.
- **Motion:** none at rest. A newly arrived gap (its `Linked Story` set since the last open, §1.2) is drawn already as a gap — the absence is the arrival; it does not animate.
- **VoiceOver:** each role static text; each gap a button with the story's title (W2).
- **Logic:** zero rows → nothing drawn (W2). A role with an empty `Name` is skipped (never an empty line).
- **Accessibility:** Dynamic Type at AX3: the column wraps, never truncates.

### 1.2 A role leaves — he notices the absence first

- **Data:** the pipeline (Appendix A) sets a Waiting Role's `Linked Story` when its story is written. Nothing is deleted; the role row stays, now a gap.
- **Read:** `FeedStore` keeps `bindu.waiting.linked` (`[roleId]`, the gaps seen at the last open). At each load, `newlyLeft = gaps − bindu.waiting.linked`. STATE.md: FORGET clear (the roles stay; only the memory of having seen them goes) · CARRY —.
- **The arrival** — `ArrivalKind.roleLeft` (W5's kind; if W5 did not build it, add it to `ArrivalRules` here with weight **8** in R5, eligible iff `newlyLeft` is non-empty and today is not a rope day):

  - recorded in `bindu.arrival.surfaced` (kind `roleLeft`, id = the story's record id), so *what found you* lists it as the story's title.

## 2 · The composing pipeline (Track 1 creates it; Track 2 builds nothing for it)

**What it is.** A recurring scheduled cloud task (Appendix B), running nightly between his sessions, that reads the Codex and the base and writes Feed rows — and nothing else. It is the house's second clock: *Claude's authoring clock meets the app's living clock* (readers/12 §4 #13). The app never calls a model for any of it; it reads rows.

**Created with notifications off** — `notifications: {}`. This is a house law (CONTRACT §7), not a preference; the tool's defaults would send push and email on every run.

**The shape of one run** (the standing prompt, Appendix A, is the authority; this is its outline):
1. **Ground** — read the repo's `CONTRACT.md`, `GAMEPLAN.md` §2 / §4 / §8 / §10, `readers/20-prior-readers.md` §D, `scores/W2.md` §1.4 and §5 (the marks and the 21 grammars), and one finished manifest (`content/C1-A-manifest.md`) for the exact form of a story and its children.
2. **Delivery mode** — if the eight new Room rows are `Live`, the house has been given: write `Live`. Otherwise write `Staged`. (Appendix B creates the task after the flip, so in practice every run writes Live; the check makes an early or re-created task safe.)
3. **Intake** — Codex rows dated on or after **2026-10-13** that the house has not yet received (no `Planted` row and no Story carries their Codex ID), excluding build-proof rows. This includes the Door's spoken answers and the in-app Codex section (`Source App = Bindu Feed`), which are now the main source (readers/21 §16: Codex intake is near zero).
4. **The truth screen** on raw speech — explicit, entry by entry: set aside whole (a `Planted` row `Archived`, reason class only) or plant.
5. **Plant** — one `Planted` row per received entry, in its room, the same night.
6. **Ripen** — on a later night (the seed is at least two days old), compose at most **four** stories from planted seeds, and let at most **two** Waiting Roles leave (compose their stories, link them). Short Door answers stay planted as complete seeds unless three or more rhyme into one story.
7. **Compose** by the house method (recognition first; room by felt quality among the 21; teller; Gaia → Sid → Arch → Sakshi; title last; gates; coordinates; marks; five children; rhyme and convergence line; song).
8. **Write and verify** — batches ≤ 15, `typecast: true`, field IDs, read back every record, five children each, links on both sides where the contract says.
9. **Report** — the run's own final message (the task's transcript) lists what was planted, set aside (by class only), ripened and written, with record IDs. It never messages Ashrey and never sends anything anywhere.

**What it never does:** edit or delete any existing record or field; rename anything; touch Ash Comments, the Lalita Pass, the sealed list, sibling tables, the Codex table (read only — its `Status` field triggers automations), App Activity; ask anyone anything; write a story live for a waiting screen; carry his past voice as his (the Return's law); use the canon chip.
