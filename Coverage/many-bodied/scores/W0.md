## 3 · The G0 hold engine (native)

**File:** `Components/HoldEngine.swift`. One engine for every hold. It is built from padakarshini G0 (`/mnt/skills/user/padakarshini/references/gestures.md` §G0) and moved to the display link.

```swift
@MainActor final class HoldEngine: ObservableObject {
    struct Spec { var up: Double; var down: Double = 0.62; var name: String }   // seconds; name = the act ("open it now")
    enum Drive { case hand, key, stillness }
    @Published private(set) var p: Double = 0          // 0…1
    @Published private(set) var phase: Phase = .rest   // .rest · .holding · .committed · .draining · .done
    var spec: Spec
    var onCommit: () -> Void = {}                      // the visual commit, at p == 1 (haptic latch)
    var onComplete: () -> Void = {}                    // THE ACT — only on release after commit
    func press(_ d: Drive = .hand)                     // target = 1; start the link if stopped
    func release()                                     // committed → done + onComplete(); else target = 0 (drain)
    func cancel()                                      // view disappeared: drain silently, never complete
}
```

- **Tick** (`CADisplayLink`, `preferredFrameRateRange = 60…120`), with `dt = min(1/15, link.targetTimestamp − last)`:
  - `p += target > p ? dt/spec.up : −dt/spec.down`, clamped to [0, 1].
  - At `p ≥ 1` while holding and not yet committed: `phase = .committed`, then `onCommit()`. The link stops (nothing animates while held at full).
  - At `p == 0` with target 0: `phase = .rest`, and the link stops. **No loop runs at rest.**
- **Never fails.** An early release drains at `down` (0.62 s default; 0.75 for the Turning). No failure sound. No jolt to zero. Pressing again resumes from the current `p`. It never restarts from 0, which is the `HoldEmber` fault.
- **Act on release.** Navigation, writes, permissions and audio starts all happen in `onComplete`. Only the visual and haptic commit happen at the threshold.
- **Durations by meaning:**
  - **commit, 0.7–1.3 s:** FloorDoor 1.25, peel 1.25, Gift 1.2, empty summit 1.2, Call go-down 1.3;
  - **ceremonial, 1.1–2.9 s with a drain:** Resonance Depth 1.5, seals 1.6, rewind 2.2, letter early 2.2, Compose 2.3, Call lay 2.6, Signal tratak 2.6, Turning 2.9;
  - **over 3 s only where the hold *is* the act:** the Light's carve (scene-authored, up to 4.2).
  - Existing holds keep their designed length (*"a hold is the hold it was designed to be"*).
- **Stillness drive.** `press(.stillness)` is called by the host when `Stillness.stillNow ≥ threshold` (`Reception/Reception.swift:155-190`). Any touch first calls `release()` (draining what stillness gave), then the hand's own `press(.hand)` continues from the current `p`. Thresholds live in GESTURES.md (the Turning 6.0 s; `.lit` 4.6 s).
- **Keys.** A hardware keyboard's held Return or Space on the focused control calls press/release (`.onKeyPress(phases: [.down, .up])`, iOS 17+). Key repeat is ignored.
- **Reduced Motion.** Duration and order are unchanged. Only the fill is drawn in quarter steps (`(p*4).rounded(.down)/4`), and the end state shows at completion.
- **Haptics** (`CHHapticEngine`; fall back to `UIImpactFeedbackGenerator`):
  - press: a transient at intensity 0.4, sharpness 0.3;
  - holding: a continuous event whose intensity ramps 0.15 → 0.6 with `p`, sharpness 0.3;
  - commit: a medium impact (the latch);
  - early release: nothing.
- **Accessibility.**
  - The host view: `.accessibilityAddTraits(.isButton)`, label = `"hold to " + spec.name`, `.accessibilityAction(named: spec.name) { engine.completeForAccessibility() }`. This runs `onCommit` and then `onComplete`, and is the VoiceOver door, equal to the hold.
  - While holding, `accessibilityValue` is `"holding"`, then `"held"`. **Never a percentage.**
- **Views.** `HoldRing` (the old HoldPress look) and `HoldEmberView` (the old HoldEmber look) take `@ObservedObject engine` and draw `p`. The ring: track at 0.22, arc `trim(0,p)` 1.6 pt round, centre dot `6 + 8p`. The ember: track at 0.14, arc 1.4 pt, dot `10 + 6p`, shadow `10 + 10p`, breathing ×(0.94 + 0.12·breath).
- **Gesture binding.** A `DragGesture(minimumDistance: 0)`: `onChanged` → `press` once; `onEnded` → `release`. Movement over 24 pt calls `release()` (padakarshini's *what cancels a hold*). `onDisappear` → `cancel()`.
- **Tests** (`Bindu FeedTests/HoldEngineTests.swift`, driving `tick(dt:)` directly):
  - a full hold completes only on release;
  - an early release completes nothing and returns to 0 in `down` seconds;
  - press, release, press resumes from the drained value;
  - Reduced Motion keeps the duration;
  - the accessibility action completes.
